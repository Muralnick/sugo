# Testing, benchmarks and performance

## Golden rule

Savings and quality are always reported together: *"−68% tokens with 99.6% of content preserved"*. A savings figure without a content-preservation figure is meaningless.

## Test types

| Type | Verifies | Examples |
|---|---|---|
| Unit | Single components | A cleaner, a language pack, config merging, locked policies |
| Property-based (Hypothesis) | Invariants over thousands of generated inputs | Cleaning never adds text; every removal has a reason; no chunk exceeds its budget; cleaning is idempotent |
| Invariant (`@pytest.mark.invariant`) | `PRINCIPLES.md` | One or more per principle |
| Contract | Public promises | JSON Schemas, MCP tool schemas, exit codes, error codes, CLI help |
| Golden | Expected output for corpus documents | Output changes must be approved explicitly |
| Integration | Full pipeline per level and profile | File → JSONL |
| Security | Hostile corpus | Zip bombs, zip slip, malformed PDFs, huge images, hidden text, symlink loops, XXE |
| Disaster recovery | Recovery scenarios | Kill mid-job and resume, corrupted cache, migration rollback, **backup restore** |
| Install | Each profile in a clean environment | Measures real install size (feeds setup cards) |
| Language packs | Hard cases per language | Hyphens vs compounds, furigana, decomposed Hangul, inverted Spanish marks |
| Mutation (weekly) | Test strength | Injected bugs must be caught |

## Corpus

| Source | Value |
|---|---|
| **Synthetic documents** generated by the project | Exact ground truth: PDFs with headers, two columns, tables; fake chat and code screenshots incl. dark mode, in all eight languages |
| **EUR-Lex** | Same legal text in Italian, Spanish, French, German and English; reuse permitted; ideal for cross-language comparison and legal recipes |
| Public-domain texts (Project Gutenberg, Wikisource, Aozora Bunko) | Real books for long-document tests |
| Public benchmarks (OmniDocBench, ExtractBench) | Comparability with other tools |

Chinese and Korean sources to be selected with licence care. The corpus lives **outside the main repository** with a manifest, checksums and per-file licences. No private documents without authorisation.

## Metrics

| Area | Metrics |
|---|---|
| Text | Character and word error rate vs ground truth |
| Structure | Reading order, heading detection, table structure (TEDS) |
| **Cleaning** | Noise removed and **content lost** — the most important metric of the project |
| VLM | Hallucination rate |
| Tokens | Reduction per document type; comparison with image cost per provider |
| Performance | Time per page, peak RAM, startup time, disk |
| RAG usefulness (optional) | Questions with known answers: the answer-bearing chunk must rank in the top-k with keyword search |

## Regression gates

| If a change… | Then |
|---|---|
| Increases content lost | Blocked |
| Reduces token savings by more than 1 percentage point | Blocked |
| Increases recognition errors | Blocked |
| Slows down or uses more memory by more than 10% | Blocked |

Unblocked only with a written justification (ADR or changelog note). CI timings are noisy: medians and relative thresholds. Results are archived and README charts update automatically. GPU tests run on the reference machine before each release (`sugo bench --suite gpu`), and the report is attached to the release.

## Performance targets (initial, to be validated)

Reference machine: 8 GB RAM, 4 cores; no GPU for `lite` and `normal`.

| Operation | Target |
|---|---|
| CLI startup (`sugo --help`) | < 0.3 s |
| Clipboard screenshot → text, warm engine | < 2 s |
| Same, cold | < 6 s |
| Native PDF, `lite`, including cleaning | ≥ 20 pages/s |
| Scanned page, `lite` OCR on CPU | 1–3 s |
| Complex page, `normal` on CPU | 3–8 s |
| Peak RAM | `lite` < 1 GB; `normal` and `quality` < 2.5 GB (+ VRAM) |

Measured so far (targets unchanged until a decision is recorded):

| Operation | Measured | Script |
|---|---|---|
| Dense phone screenshot (30 lines) → text, warm, `lite` small models | 7.4 s, 411 MB peak, 0% character errors (October 2026) | `benchmarks/ocr_speed.py` |
| Same, on a 2010 desktop (i5-650: 2 cores, 4 threads, no AVX; 8 GB) | 13.7 s, 411 MB peak, 0% character errors (2026-11-03) | `benchmarks/ocr_speed.py` |
| Same, on the reference machine (i5-10300H) | 1.5 s, 347 MB peak, 0% character errors (2026-11-03) | `benchmarks/ocr_speed.py` |
| Native PDF, 100 generated pages with header, footer and page numbers, `--no-cache`, same 2010 desktop | 3.6 s including startup (about 28 pages/s), 98 MB peak (2026-11-03) | `/usr/bin/time -f "%e s %M KB" sugo convert --no-cache` |
| CLI startup (`sugo --help`), same 2010 desktop | 0.47 s median of 5 (2026-11-03) | shell timing |

Step 8 corpus benchmark, on the reference machine (i5-10300H), `lite`, 31 documents in Italian, Spanish, French, German and English — synthetic PDFs, an XLSX table, chat and code screenshots, and the real text of EU Regulation 261/2004 from EUR-Lex (2026-11-03, `benchmarks/corpus_bench.py`; full report in `benchmarks/results/`):

| Document | Tokens saved | Content lost | Median time |
|---|---|---|---|
| Native PDF report (5 pages: running header, footer clause, page numbers) | 33–38% (avg 35%) | None | ~1.0 s |
| EUR-Lex Regulation 261/2004 (12–14 pages of real legal text) | 2.9–3.5% (avg 3.2%) — mostly substantive text, little page furniture | None | ~1.2–1.3 s |
| Chat or code screenshot, Markdown vs sending the image itself | 94–98.5% cheaper, across Claude, Gemini and OpenAI's own formulas | 0–7.1% OCR character error on accented text (it/es/fr); 0% on de/en | ~1.0 s |
| Whole 31-document run | — | — | 372 MB peak RAM |

The EUR-Lex sample is fetched separately (its text, not Sugo's typeset PDF, is the original: see `benchmarks/corpus_eur_lex.py` and the manifest it reads) and kept outside the repository with its licence and checksums (this section, above); `benchmarks/corpus_bench.py` runs the synthetic corpus alone when it is absent.

## Logging and diagnostics

| Aspect | Decision |
|---|---|
| Format | Structured JSON lines with rotation; readable console output |
| Tracing | Job and page ids across processes |
| Privacy | Never document content; **no file names** at default level (a name can itself be sensitive); explicit local debug flag only |
| Bug reports | `sugo doctor --report`: diagnostics, sanitised logs, config without secrets; reviewed by the user before sharing |
| Telemetry | None, ever |
| Personal statistics | Local only: `sugo stats --history` |
